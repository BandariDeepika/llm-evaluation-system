# M1.1 — Research & Technical Understanding

## 1. Project Overview

The project is an Automated LLM Evaluation and Hallucination Detection System.

Large Language Models (LLMs) can generate useful answers, but they may sometimes produce incorrect, irrelevant, incomplete, or unsupported information. The purpose of this project is to automatically evaluate AI-generated responses and identify possible hallucinations.

The system evaluates responses using multiple dimensions such as relevance, factuality, faithfulness, completeness, semantic similarity, and hallucination detection.

---

## 2. LLM Evaluation

LLM evaluation is the process of measuring the quality and reliability of responses generated by a Large Language Model.

The main evaluation dimensions used in this project are:

- Relevance — checks whether the response answers the given question.
- Factuality — checks whether the information is factually correct.
- Faithfulness — checks whether the response is supported by the available evidence.
- Completeness — checks whether the response contains the required information.
- Semantic Similarity — measures similarity between the AI response and a reference answer.
- Hallucination Detection — identifies unsupported or incorrect claims.

---

## 3. Hallucination Detection

Hallucination occurs when an AI model generates information that is false, unsupported, or not present in the available evidence.

In this project, retrieved knowledge-base information can be used as evidence to check whether claims in the AI response are supported.

The system reports:

- Whether hallucination is detected
- Hallucination severity
- Unsupported claims
- Explanation of the result

---

## 4. RAG Architecture

RAG stands for Retrieval-Augmented Generation.

A RAG system retrieves relevant information from a knowledge base and uses the retrieved information to improve the reliability of AI responses or their evaluation.

The retrieval pipeline used in this project is:

TruthfulQA + SQuAD
→ Preprocessing
→ Chunking
→ Embeddings
→ ChromaDB
→ Relevant Context Retrieval
→ Response Evaluation

---

## 5. Embeddings

Embeddings represent text as numerical vectors.

They allow the system to compare the meaning of text and retrieve information that is semantically related to a question.

Sentence-transformers are used as the embedding approach in the project.

---

## 6. Vector Database

ChromaDB is used as the local vector database.

It stores document embeddings and allows the system to retrieve relevant chunks based on a user's question.

---

## 7. LLM-as-a-Judge

LLM-as-a-Judge is an approach where a language model evaluates another AI-generated response according to predefined evaluation criteria.

It can be used to evaluate qualities such as correctness, relevance, and helpfulness.

The current implementation provides a deterministic rule-based baseline, while an LLM-based judge can be integrated later.

---

## 8. RAGAS and TruLens

RAGAS and TruLens are existing frameworks for evaluating LLM and RAG-based applications.

RAGAS provides metrics for evaluating aspects such as faithfulness, context relevance, and answer quality.

TruLens provides tools for evaluating and monitoring LLM applications.

These frameworks were studied as part of the research phase and helped in understanding standard LLM/RAG evaluation approaches.

---

## 9. Datasets

### TruthfulQA

TruthfulQA is a benchmark dataset designed to measure whether language models generate truthful answers.

It is useful for studying truthfulness and hallucination-related behavior.

### SQuAD

SQuAD stands for Stanford Question Answering Dataset.

It contains questions, answers, and supporting passages and is useful for question-answering and retrieval evaluation.

Both datasets are obtained through the Hugging Face datasets library.

---

## 10. Evaluation Scoring

The system evaluates responses using the following dimensions:

| Dimension | Weight |
|---|---:|
| Relevance | 20% |
| Factuality | 25% |
| Faithfulness | 25% |
| Completeness | 15% |
| Semantic Similarity | 15% |

The overall score is calculated using a weighted average of the available evaluation dimensions.

If a dimension is unavailable, the remaining weights are normalized.

## 12. Proposed Implementation Strategy

The system is implemented using the following workflow:

1. User provides a question and AI-generated response.
2. Optional reference answer or source document can be provided.
3. The system can retrieve relevant evidence from the local knowledge base.
4. Evaluation modules analyze the AI response.
5. Relevance, factuality, faithfulness, completeness, and semantic similarity are calculated.
6. Hallucination detection checks the response against available evidence.
7. The individual scores are combined into an overall score.
8. The final assessment is displayed through the Streamlit interface.
